## 六、检索范围贯通与联网来源重构（2026-09-11）

### 背景

复核时发现三个问题：① UI 的「分析市场」（国内/海外）只是摆设，没影响检索；② 国内检索过度依赖电商平台；③ 联网来源存在模型编造的虚假 URL。

### 1. 定位：qwen 联网的 URL 是编造的

解析 qwen 的原始响应发现，**compatible-mode 接口根本不返回 `search_info` 字段**（顶层只有 model/id/choices/created/object/usage，message 只含 content/role）。模型拿不到检索结果，只能在正文里凭记忆写 URL，实测产出大量顺序数字的伪链接：

```
https://detail.tmall.com/item.htm?id=61234567890   ← 1234567890
https://item.jd.com/100012345678.html              ← 12345678
https://www.jd.com/product/100088888888.html       ← 88888888
```

而真实京东链接格式是 `item.jd.com/product/AZpp1PsHtg6AAtu0SHpwOQ.html`（带 hash）。最新实测 25 条唯一来源中 16 条出自 qwen、基本全假。

**根因是接口用错了，不是模型能力问题**：改调百炼原生端点 `/api/v1/services/aigc/text-generation/generation`，配 `search_options: {enable_source: true}`，立刻拿到真实 `search_results`（含 site_name/title/url）。实测可用模型：qwen-plus、qwen-max、qwen3-max、qwen-turbo；qwen3.7-plus 在原生 API 报 400，因此**搜索模型与提取模型解耦**——搜索用 qwen-plus 拿真 URL，提取仍用 3.7-plus/3.8-max。

修复后 `qwen_search` 只取 `search_info.search_results`，**完全忽略模型正文**，从源头消除编造。

### 2. 检索范围贯通

- 新增 `MARKET_PROFILES`，把「国内电商/海外电商」落到 region、币种、检索语言、来源侧重、检索词来源词
- 检索词按市场生成：国内用"官网/评测/参数/对比"，海外用"official/review/specifications/comparison"
- 检索要求按市场动态生成，不再硬编码"优先京东天猫"

**实测对比（同一产品"蛋白粉"）**：

| | 国内电商档 | 海外电商档 |
|---|---|---|
| 检索词 | 蛋白粉 国内电商 主流品牌 市场份额；2023-2024 中国蛋白粉品牌排行榜 专业评测 | best selling protein powder Amazon US UK DE；top rated whey protein powder iHerb Vitacost |
| 竞品集 | 肌肉科技、汤臣倍健、康比特、维力维、欧普特蒙 | Transparent Labs、Legion、Ascent、Dymatize ISO100、Garden of Life |

两档产出完全不重叠，范围选择真正生效。

### 3. 多来源、不再只盯电商

- 检索要求明确覆盖品牌官网、行业媒体与专业评测、百科、行业研报，电商降为"价格与在售佐证之一"
- 正文抓取优先级：电商详情页（jd/tmall/taobao/1688/amazon…）反爬重，排到媒体/评测/官网之后
- **实测国内档来源构成**：观研报告网、新食界、新浪财经（行业报告）、界面新闻（媒体）、知乎、iivd.net（社区）、PDF 研报——**无一电商详情页**

### 4. 反编造防线

- `url_is_dead()`：并发校验 qwen 来源，只判定确定的死链（404/410）；403/429/超时视为存活，避免误杀反爬站
- 过滤 AI 输出的 `[Competitor Brand]` 模板占位符，杜绝占位串进入检索词

### 5. 本轮修复的两个 bug

- **竞品发现被截断**：发现型检索词排在最后，被 `[:6]` 配额砍掉 → 结果只盘点单一品牌（20 条全是 Myprotein）、没有横向对比。改为优先排序后，同一输入产出 10 个品牌的横向对比
- **占位符污染**：类目识别失败时 `待确认产品类别` 被直接拼进检索词（"蛋白粉 待确认产品类别 价格与套餐 官方"）。新增 `query_subject()` 在类别不可用时退化为主体品牌名

### 6. 效果

修复后同一产品可提取到**可横向比较的量化参数**：维力维蛋白质 95.8g/100g、汤臣倍健>90g/100g、ON 亮氨酸占比 38.2%、康比特肽链分子量<1200 道尔顿、水解率 78.6–94.1% —— 均为网页原文抽取、置信度 0.9、带 source_id 溯源。

### 7. 调研结论（联网方案选型）

对比了百炼原生、智谱 GLM Search、Kimi、百度千帆、Perplexity Sonar 等可溯源联网方案，以及博查/秘塔/Tavily/Exa/Brave/SerpAPI 等独立搜索 API。结论：**不必更换厂商**——百炼原生 API 即可拿到真实 URL；独立搜索底座中博查 BochaAI、秘塔、百度千帆在国内可用性好（本次未接入，作为后续备选）。

## 七、类别识别修复与前端改版（2026-09-11）

### 1. 修复 AI 类别识别失败（根因是 schema 未约束，不是模型能力）

**现象**：输入"蛋白粉"时，识别结果始终是"待确认产品类别"，维度也总是固定模板。

**定位**：打印 AI 原始返回发现，模型返回的顶层键是 `{meta, input_analysis, comparison_dimensions, search_plan}`，而程序期望 `{document_profile, entities, observed_fields, ...}`。原因是 prompt 只写了"请返回与 file-intake-v3 相同的 JSON 顶层结构"，**却没有列出具体键名**，模型于是自由发挥。normalize 只认固定路径，导致类别、维度、实体**全部被静默丢弃**，退回本地兜底值。模型其实识别对了类别（`input_analysis.category_inference.primary_category = "运动营养/膳食补充剂"`），只是没人去读。

**修复**：抽出 `SCHEMA_SPEC` 常量写死键名清单（并明确禁止使用 dimension_name、rationale 等别名）；normalize 增加漂移路径兜底；类别确实无法识别时用产品名替代占位串。

**效果**：类别识别为"运动营养/膳食补充剂"（conf 0.6），比较维度变为模型生成的专业维度——蛋白质纯度与含量、原料来源与类型、电商售价与规格性价比、口味与溶解性评价、品牌信誉与认证资质。

### 2. 检索主体改用具体产品名

修复过程中发现一个反直觉的问题：用抽象品类名（"运动营养/膳食补充剂"）作检索词，会搜出"竞品调研方法论"文章和行业研报，产品参数一条都提取不到；换回具体产品名（"蛋白粉"）立刻能搜到真实品牌横向对比。据此把检索词主体改为优先使用用户输入的产品名。

### 3. 搜索提速

- qwen 搜索模型换 `qwen-turbo`（实测 6s，qwen-plus 需 20-40s）
- qwen 只跑前 3 条发现型检索词，细节补齐交给 Tavily
- 完整流程从 83-174s 降到 **76s**

### 4. 前端改版

安装并应用 `anti-ui-slop` skill（uizze 出品，被 github/awesome-copilot 收录）重做界面样式：

- 去掉药丸形标签与圆角浅色卡片，改用**间距、对齐和细线**分组
- 数字列用 `tabular-nums` 对齐，便于横向比较
- 控件圆角统一为 4px，去掉 Streamlit 默认的大圆角
- 新增 `.streamlit/config.toml`，把主题色从 Streamlit 默认红改为墨绿，与品牌色一致
- 标题字体用 Georgia 衬线，正文用系统字体

**踩坑**：Streamlit 组件样式（styled-components）优先级高于裸标签选择器，覆盖标题字号/字体必须加 `!important`。

### 5. 交互改进

- **生成分析进度条**：一次分析要 1-2 分钟，原来界面上只有一个转圈。现在显示进度条和当前阶段（检索 xxx → 读取网页正文 → 抽取事实），用户能知道进行到哪一步
- **历史记录可回看完整报告**：原来历史页只有一张摘要表格，看不到当时的结论。现在数据库保存整份报告，选中任意一条即可展开当时的完整报告（指标、搜索用量、结论、商品信息）
- **修复分析卡顿**：排查长时间等待时发现，网页正文抓取是**串行**的——8 个页面逐个抓，每个失败还要重试一次镜像站，最坏要几分钟。改为并发抓取后明显加快
- **报告可读性调整**（按使用反馈）：① 去掉"批量待核验"填充——原先给每个"品牌×维度"的空组合都插一行"需要从原文核对"，十个品牌乘六个维度会产生几十行噪音，真实结论被淹没、报告无法直接交付；现在空单元格显示"—"，只呈现有依据的事实。② 新增"证据明细"表，每条事实一行并带"打开原文"链接，方便逐条回到来源校对。③ 横向比较表把网页原文里**实际找到的品牌**并入比较对象（原先只列候选，导致矩阵表缺行、和"关键差异"对不上）。④ 表格设固定列宽，减少横向拖动
- **界面文案与格式**：删除各模块下口语化的解释小字，只保留必要的状态信息；时间统一为"2026-09-11 00:27"格式

**数据呈现改进**（按使用反馈）：

- **候选竞品改为品牌级**：原先返回的是产品名或品类名（"增肌配方粉""植物蛋白粉"），用户关注的是品牌，已在识别环节明确要求只输出品牌或厂商名
- **评价改为归纳**：用户评价原先直接照抄原文，既口语化又冗长；改为 15-30 字的客观归纳
- **图表在缺数据时可读**：覆盖热图原先对空值渲染"待补"，缺数据时整图都是占位；改为裁掉全空行列、空值不渲染文字；指标不足三项时不生成雷达图
- **横向比较改版式**：宽表格需要横向拖动且信息密集，改为**按品牌分组**的对齐列表，一行读一个对象

### 9. 从"信息收集器"到"分析助手"（2026-09-11 深夜）

以产品经理视角复盘后，最突出的问题不是缺功能，而是**报告只罗列数据、不给判断**——用户拿到后还得自己读、自己想、自己写给老板。据此做了两项改造：

**关键发现（新增"一页结论"）**：报告顶部由 AI 基于**已有来源的事实**归纳 3–5 条对比性结论——谁在哪个维度领先、差距多大、几家的共性是什么。约束是只能用给定事实、不得引入外部知识、不得编造数字；事实不足时宁可不写。这让报告有了可直接放进汇报的结论层。

**补齐价格这条腿**：检查发现 15 个商品记录中 **0 个有价格**。根因是此前为避开反爬的电商，来源全成了评测和行业研报，而**价格恰恰在电商与比价页上**——需求侧规避反爬时把价格来源一起规避掉了。三处调整：

- 价格类维度使用专门检索词（国内「价格 报价」/ 海外「price quote」），不再与其他维度共用泛化词
- 正文抓取优先级把比价站（什么值得买、中关村在线等）提到最前，电商详情页仍排最后
- 抽取提示里明确 `price` 为重点字段，售价、活动价、价格区间、单价（元/100g）都要提取，不同规格不合并

**界面色调**：落地页深色块由近黑改为与品牌同系的深墨绿渐变，不再与整体跳色；同时清理了 `use_container_width` 弃用写法。
