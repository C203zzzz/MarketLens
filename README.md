# MarketLens · 竞品情报工作台

把散落在公开渠道的竞品信息，整理成**可横向比较、且每条结论都能回溯到原文**的分析报告。

支持两种入口：上传已有资料（Excel / CSV / PDF），或只输入一个产品名称。

---

## 它解决什么问题

市面上的 AI 竞品工具已经能"一键生成报告"，但实际用起来有三个通病：

| 通病 | 表现 | 后果 |
|---|---|---|
| **编造** | 大模型"回忆"出看起来合理的价格、参数 | 拿去做决策会出事 |
| **不可核对** | 给结论不给来源，或给一个打不开的链接 | 无法验证，等于没给 |
| **不可比较** | 各家信息维度不同，拼不成一张表 | 还是要人工整理 |

MarketLens 的产品假设是：**用户不缺信息聚合能力，缺的是可信度**。因此把"可溯源"做成硬约束而不是可选项：

- 只有网页**原文**中明确写出的内容才会成为事实，搜索摘要只用于发现来源
- 表格中的「—」表示该指标暂无有依据的数据，**系统不会用推测填空**
- 同一字段出现矛盾值时全部保留并列入待确认，由用户判断
- 不绕过登录、付费墙、验证码或反爬机制

---

## 核心能力

**多品类通用**。品类识别、比较维度、品牌判断全部由模型按实际产品判定，代码里不含任何行业关键词表。实测六个差异极大的品类，全程零代码改动：

| 品类 | 入口 | 识别出的比较维度 | 竞品横向覆盖 |
|---|---|---|---|
| 保健品（蛋白粉） | 输入产品名 | 蛋白质含量、配方纯净度、适用人群… | 6/6 对象 |
| 实验室仪器（培养箱） | 上传 Excel | 型号、单价、总价、备注 | 资料内 4 品牌各满格 |
| 酶标仪（Tecan） | 上传 PDF | 光学系统、灵敏度、通量、温控… | 分析对象 6/6 + 竞品 5/6 |
| SaaS（飞书） | 输入产品名 | 定价模式、开放集成、数据合规… | 5/6 对象 |
| 服装（冲锋衣） | 输入产品名 | 防水透气、面料工艺、功能设计… | 5/5 对象 |
| 家电（扫地机器人） | 输入产品名 | 清洁能力、导航避障、续航… | 5/5 对象 |

**每条事实可溯源**。证据明细里每行都带「打开」链接直达原文；读取失败的来源会明确标注，不会当成已核验。

**结论而非数据堆砌**。报告首屏是 3-5 条对比性结论（"谁在哪个维度领先、差距多少"），而不是把参数平铺给用户自己看。

## 迭代历程

项目经过 10 轮迭代。完整记录见 **[docs/迭代历程.md](docs/迭代历程.md)**，这里摘几条最能说明判断过程的：

**第 3 轮**：来源链接点开是 404。看起来是"校验不严"，实际是**接口选错了**——兼容接口不返回检索来源，模型只能凭记忆编造 URL。换成原生接口并只采信接口返回的来源列表。*如果按"加一层 URL 校验"的思路走，能过滤 404 但过滤不掉"看起来合理且恰好存在的链接"。*

**第 8 轮**：报告里 5 个竞品一条数据都没有。一开始以为是检索能力不够，统计调用记录才发现 **16 次搜索有 6 次纯重复**——三个搜索引擎收到完全相同的查询列表。重新分配预算后，有数据的竞品从 1/6 提升到 6/6。*每个环节单独看都正常，问题出在环节之间的资源分配。*

**第 9 轮**：每换一个品类就要改代码。原因是开发中不断补充关键词表，最多时堆了三张（维度→列名映射、维度→检索词映射、品类词后缀表）。意识到它们**都在用关键词模拟语义判断**，而系统里本来就有大模型。删掉三张表，改为"模型做语义、代码做机制"。

**第 10 轮**：28 页的 PDF 只有前几页进了模型。代码里 `[:26000]` 的整体截断造成**结构性丢失**——截断点之后的内容全没。改为按页分配预算。

## 快速开始

```powershell
python -m pip install -r requirements.txt
python -m streamlit run app.py --server.port 8504
```

浏览器打开 `http://localhost:8504`。**没有任何 API Key 时也能跑**（走本地演示模式），配置 Key 后启用完整能力。

## API 配置

推荐使用环境变量，或项目内 `.streamlit/secrets.toml`（参考 `.streamlit/secrets.example.toml`）。

> **真实 Key 不要写入 `app.py`、README、SQLite、报告或任何会提交到仓库的文件。**

文件识别走阿里云百炼兼容接口：

```toml
FILE_ANALYSIS_API_KEY = "替换为百炼 API Key"
FILE_ANALYSIS_MODEL = "qwen3.7-plus"
FILE_ANALYSIS_MODEL_DEEP = "qwen3.8-max"
```

联网检索走百炼**原生**接口——compatible-mode 不返回真实来源：

```toml
QWEN_SEARCH_API_KEY = "替换为百炼 API Key"
QWEN_SEARCH_MODEL = "qwen-turbo"
```

其他搜索工具（可选，按需配置）：

```toml
BOCHA_API_KEY = ""
TAVILY_API_KEY = ""
EXA_API_KEY = ""
SERPAPI_API_KEY = ""
SEARCH_PROVIDERS = "qwen,bocha,tavily,exa,serpapi,brave"
```

## 工作流程

1. 选择检索范围：国内电商 / 海外电商（决定检索语言与来源侧重）
2. 上传产品资料，或直接输入产品名称
3. 模型识别产品类别、品牌/产品/型号、已有字段、比较维度与检索计划
4. 按比较维度生成检索词，依次调用 qwen（原生联网）、bocha、tavily；来源不足时再用 exa、serpapi、brave 补充
5. 按规范 URL 与内容哈希跨供应商去重合并
6. 只读取公开可访问的网页正文；搜索摘要只用于发现，不直接成为事实
7. 输出一页结论、多指标横向比较、证据明细（附原文链接）、来源清单与确认队列

## 当前边界

- PDF 当前支持文本型文件；扫描件尚未接 OCR
- PDF 内嵌表格按正文文本处理，未做结构化解析
- 天猫、淘宝、拼多多、抖音商城的商品详情页没有公开索引，且价格字段有字体加密保护；这几家的价格主要通过比价站与专业评测页获得，**不绕过反爬**
- 仪器类产品的报价多为询价制，公开渠道无价格，报告不会编造
- 用户只上传竞品清单、未说明自家产品时，系统不做猜测，报告以品类为标题
